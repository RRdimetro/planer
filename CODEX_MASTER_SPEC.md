# FOCUS OS PRO — MASTER SPECIFICATION FOR CODEX

**Статус:** утверждённые требования к реализации. **Язык приложения:** русский. **Платформа:** Windows 10/11 x64, desktop-first. **Режим:** local-first, полноценная работа без интернета. **Дизайн:** Premium Forest. **Референс учёбы:** `docs/reference/study_tracker_original.jpeg`.

## 0. Роль Codex и обязательные правила

Ты — ведущий full-stack/desktop-инженер, архитектор и QA. Твоя задача — **не нарисовать концепт**, а создать работоспособное Windows-приложение с настоящими данными, сохранением в SQLite, тестами и установщиком. Сначала изучи весь документ и референс. Выбирай практичные архитектурные решения, документируй допущения; не спрашивай подтверждения для мелочей. Ничего не объявляй готовым, пока оно не работает. Не подменяй реальные функции декоративными кнопками, демографиками и статическими данными. Если разработка происходит итеративно, в конце каждого этапа должны быть рабочий запуск, миграции и тесты. Вести `IMPLEMENTATION_STATUS.md` с выполненным/частичным/не сделанным и честными причинами. Все пользовательские интерфейсы на русском; идентификаторы в коде — английские.

Продукт представляет собой **10 экранов**: (1) Главная, (2) Планировщик, (3) Задачи, (4) Проекты, (5) Учёба, (6) Тренировки, (7) Аналитика, (8) Фокус, (9) Заметки, (10) Настройки. **Не создавать экраны «Привычки» или «Финансы»**. Если нужны связанные метрики (например регулярность тренировок), показывать их внутри соответствующего модуля, без возрождения удалённых разделов.

## 1. Техническая архитектура

- Electron stable + React + TypeScript strict + Vite + Tailwind CSS + Radix/shadcn/ui + Motion для анимации; Recharts для аналитики, Zustand для лёгкого UI-состояния, TanStack Query для загрузки/обновления данных, React Hook Form + Zod для форм.
- SQLite через `better-sqlite3` в **Electron main process**, Drizzle ORM и версионированные миграции. Не открывать DB из renderer. Использовать безопасный узкий IPC через preload и typed API. Renderer без NodeJS и без прямого доступа к `fs`.
- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true` в renderer, запрет небезопасной remote-загрузки и eval, жёсткий CSP, валидация всех IPC payload на стороне main. Запросы к БД параметризованные. Не выдавать путь произвольного файла UI без системного диалога.
- Electron-builder для portable build и установщика Windows `.exe`, корректное завершение фоновых таймеров/операций. Никакого обязательного облака, регистрации, платных API, сервера или внешней базы.
- Хранение в `app.getPath('userData')`: база, вложения и конфигурация; экспорт ZIP backup по выбранному пользователем пути. Сохранять данные при обновлении версии. Миграции при старте с транзакцией и восстановлением при ошибке.
- SQLite `foreign_keys=ON`, WAL, целостность, необходимые индексы, мягкое удаление для задач/проектов (или журнал удаления), полное удаление данных — отдельное подтверждаемое действие.
- Управление временем: хранить timestamps в UTC, отображать по пользовательскому часовому поясу; недели с понедельника, корректная смена дня, DST и пересечения полуночи. Ориентир локали: ru-RU; дата/часовой пояс настраиваются.
- Офлайн-приложение с локальными системными уведомлениями при работающем процессе; **не обещать** уведомлений, если Windows полностью выключена. Не добавлять фоновую интернет-синхронизацию по умолчанию.
- Windows-first, поддержка экранов 1366×768, 1920×1080, 2560×1440 с адекватным масштабированием. На маленьких экранах без обрезанного текста и горизонтального скролла всей страницы.
- Code style: ESLint, Prettier, TypeScript strict, typed domain services, Zod, Vitest/React Testing Library, Playwright для e2e Electron либо документированная рабочая замена. Минимум ручных шагов установки.

## 2. Дизайн-система Premium Forest

Реализовать **реально красивый, сложный и связный интерфейс**, не примитивную админку и не светлые стандартные таблицы. Визуальное направление: глубокий графит/тёмный изумруд, карточки с несколькими уровнями глубины, мягкое зелёное свечение, точная типографика, аккуратные графики, деликатная анимация, большой обзорный экран, компактная навигация. Отступы, плотность, акценты и контраст должны быть осмысленными. Декоративные горы допустимы в шапке, но не должны мешать читаемости или подменять рабочую область.

**Токены (стартовые; можно скорректировать визуально):** background `#090F0C`, sidebar `#0D1711`, surface `#122019`, elevated `#192B21`, subtle border `#2A4133`, primary green `#73D69A`, green hover `#9BE9B7`, text `#F0F7F2`, secondary text `#A0B6A7`, muted `#6F8A79`, danger `#EC8585`, warning `#E8BD6A`, info `#79B6DF`. Сохранять WCAG-подобный контраст, не кодировать статус одним цветом.

Шрифт: современный читаемый UI-шрифт с кириллицей (например Inter с подходящими fallback). Радиусы карточек ~12–18 px, таблицы компактнее. Иконки lucide-react, единые размеры 16–20. Анимации 120–220 ms, с `prefers-reduced-motion`. Поддержка hover/focus/keyboard, tooltips, modals, toaster, skeleton loading, empty/error/confirmation states. Навигация слева с 10 разделами, глобальный поиск и командная палитра `Ctrl+K`, переключение свёрнутой панели; header с датой и быстрым добавлением.

**Крайне важно:** все графики должны брать значения из SQLite/aggregator; пока пользователь ещё не создал данных — информативные пустые состояния, а не фальшивые цифры. Демоданные допускаются **только** в отдельном опциональном деморежиме, не смешивать с настоящими.

## 3. Экраны: внешний вид и интерактивность

### 3.1 Главная / Command Center
- Верх: приветствие, текущая дата, аккуратный атмосферный баннер (не более ~130 px), быстрый поиск, quick-add.
- Ряд KPI: задачи сегодня план/факт, выполнение недельного плана, предстоящие дедлайны, тренировки план/факт, фокус-время, эффективность с трендом.
- Основная сетка: слева список задач на сегодня и три приоритета, справа расписание дня; ниже график недели, последние/ближайшие работы по учёбе, здоровье нагрузки/тренировки и активные проекты.
- Drag-and-drop/resize виджетов с сохранением раскладки (не обязательно для первого вертикального среза, обязательно до релиза).
- Клик по каждой KPI/задаче ведёт к соответствующему реальному разделу.

### 3.2 Планировщик / Calendar
- Режимы День, Неделя, Месяц; главная неделя — 7 колонок, временная шкала 06:00–24:00 с прокруткой, выходные, «сегодня», текущая линия времени.
- Боковая область: backlog на неделю без дня, незапланированные задачи, фильтры по проекту.
- Drag-and-drop задач между днями и временем, resize времени, создание событий, повторы, блокировка занятых интервалов, проверка пересечений, undo.
- Отдельные типы: task, university class, commute, workout, personal event, focus block. Слоты дороги и пар можно задавать шаблонами вручную; первоначально не требовать Google Calendar.
- Счётчик: доступное время vs оценочная трудоёмкость на каждый день, индикатор перегрузки, «Предложить распределение» на основе правил (не ИИ-API), подтверждение перед применением.
- Разрешать гибкую работу во время лекций как настройку, а также ограничения по дням (например, после тренировки нельзя планировать сложные задачи) — **не зашивать конкретные пользовательские обстоятельства в код**.

### 3.3 Задачи / Task Manager
- Три вида: Kanban (Backlog/На неделе/Сегодня/В процессе/Готово), таблица и иерархический список; фильтры проект, категория, дата, приоритет, статус, дедлайн.
- Модель задачи: title, description, status, priority, impact/weight, estimateMinutes, actualMinutes derived from sessions, dueAt, plannedDate nullable, plannedTime nullable, projectId nullable, category, tags, subtask/checklist, recurrence, dependencies, attachments, createdAt, completedAt, deletedAt.
- Важна возможность **отдельного недельного списка** и назначений на день без дублирования задачи.
- Быстрое добавление, массовое изменение, горячие клавиши, поиск, сохранение фильтров, подтверждение удаления, undo на обычных изменениях.
- Снимать исходные snapshots плана недели для расчёта честной статистики.

### 3.4 Проекты / Project Hub
- Плитки с прогрессом, проектные дорожные карты, задачи, Kanban, этапы/милстоуны, зависимости, дедлайны, привязанные заметки и файлы.
- Метрики прогресса по выполненной взвешенной трудоёмкости, оценка остатка и прогноз завершения **с отметкой, что это прогноз**.
- Не путать YouTube/личные проекты с учебными предметами; можно связать предмет с проектом по желанию.

### 3.5 Учёба / University Tracker — **ОБЯЗАТЕЛЬНАЯ ТОЧНАЯ ПЕРЕНОСКА РЕФЕРЕНСА**

Это **простая в использовании таблица отметок**, а не перегруженная система сдачи документов. Центральное действие — один клик по статусу «выполнено/не выполнено», с сохранением. Сохранить две видимые области, соответствующие screenshot:

**A. Сводка по предметам** (сверху или слева широкая): колонки `Предмет | РК написано | РК всего | ДЗ сдано | ДЗ всего | Экз | Итог`.

Начальные значения из изображения (не придумывать заполнение пустых «Экз» и «Итог»):

| Предмет | РК написано | РК всего | ДЗ сдано | ДЗ всего | Экз | Итог |
|---|---:|---:|---:|---:|---|---|
| АСОИУ | 0 | 1 | 0 | 0 | пусто | пусто |
| Англ яз | 1 | 3 | 1 | 1 | пусто | пусто |
| Модели данных | 0 | 1 | 0 | 1 | пусто | пусто |
| Программирование | 0 | 2 | 0 | 1 | пусто | пусто |
| Правоведение | 1 | 2 | 0 | 1 | пусто | пусто |
| Теорвер | 0 | 3 | 1 | 3 | пусто | пусто |
| Физика | 0 | 2 | 1 | 4 | пусто | пусто |
| Экология | 0 | 2 | 0 | 2 | пусто | пусто |
| Электротехника | 2 | 4 | 0 | 1 | пусто | пусто |

Проценты сводки вычисляются из текущих значений. Для счётчиков РК/ДЗ, где screenshot даёт только агрегаты, **не выдумывать факты о номерах сданных работ**: хранить `completedCount` и `totalCount` как исходные агрегатные значения с инкрементом/декрементом при клике или компактным редактированием; детализированные записи создавать только когда пользователь сам захочет. Если пользователь добавляет детализацию, обеспечь явную конвертацию с сохранением непротиворечивого счёта, не удваивать выполненное. Пустой `Экз` и `Итог` — `null`, не `false`.

**B. Детальные статусы работ** (таблицы/accordion по дисциплине и типу, каждая строка этапа):

1. **Физика лабы**, №1–6, этапы `Написана`, `Выполнена`, `Защищена`. По изображению:
   - Написана: №1,2,3,4 = `+`, №5,6 = `-`;
   - Выполнена: №1,2,3,4 = `+`, №5,6 = `-`;
   - Защищена: №1,2,3 = `+`, №4,5,6 = `-`.
2. **Физика ДЗ**, №1–4, этапы `Решена`, `Сдана`, `Защита теор`, `Защита прак`:
   - №1: `+` по всем четырём этапам;
   - №2: `+` у `Решена`, `Сдана`, `Защита прак`; `Защита теор` на изображении без знака — хранить `unknown`/`null`, **не считать выполненным**;
   - №3–4: на изображении пустые клетки; хранить `unknown`/`null` (не утверждать, что работы не выполнены).
3. **ЭлТех лабы**, №1–4, этапы `Выполнена`, `Защищена`:
   - №1,2: `+` оба этапа;
   - №3,4: пусто (`unknown`/`null`).
4. **МД лабы**, №1–6, этапы `Выполнена`, `Защищена`:
   - №1,2: `+` оба этапа;
   - №3,4,5,6: явные `-` оба этапа.

**Правила статусов:** `done`, `not_done`, `unknown` — 3 состояния, чтобы отличать `+`, `-` и пустую ячейку; **клик** переводит в `done`, повторный — `not_done`; контекстное меню/Alt-click — `unknown`. Не заставлять пользователя проходить три состояния при каждом обычном клике. Явно показывать зелёную галочку, пустой квадрат/тире и «?» для неизвестного, с легендой. Цвет не единственный индикатор. Изменение каждой ячейки атомарно сохраняется в SQLite; обновляет соответствующие агрегаты подробных работ и статистику.

Не смешивать заголовочные числовые столбцы и данные. Статус работы и статус этапа — разные сущности. Можно добавлять предметы/наборы работ/этапы/номера в UI, переименовывать и менять общее число РК/ДЗ, с подтверждением при удалении данных. `Экз` и `Итог` — настраиваемые необязательные значения/оценки с сохранением `null`. Кнопки «Добавить предмет», «Добавить работы», «Изменить количество», быстрые фильтры «Только незавершённые», «Нуждаются в защите».

На странице по умолчанию **одновременно видны сводка и подробные работы**, как на Excel, но в стильном тёмно-зелёном оформлении. Удобный горизонтальный скролл только внутри правой таблицы, sticky названия этапов и номеров. На 1366×768 не терять элементы. Пользователь не должен заходить в 5 вложенных форм, чтобы отметить одну защиту. При необходимости добавить `Ctrl+Z` undo после изменения.

Стартовый импорт из фотографии реализовать **детерминированным seed** из значений выше, показывать диалог «Импортировать учебный прогресс из примера?» при первом запуске/настройке, **не перезаписывать** существующие пользовательские данные при повторном запуске. `docs/reference/study_tracker_original.jpeg` — визуальный эталон. В будущем допускается импорт CSV/XLSX, но не придумывать сейчас OCR.

Учебную аналитику вынести на страницу Insights, здесь же ограничиться прогрессом по предметам, количеством работ «осталось выполнить» и «осталось защитить», основанным только на известных статусах (неизвестные указывать отдельно). **Не предполагать**, что все зачёты/экзамены уже сданы.

### 3.6 Тренировки / Fitness Studio
- Календарь недели и журнал, виды тренировки: бег, зал/силовая, другое; пользователь создаёт свои шаблоны.
- Запись факта: date/time, duration, type, perceived effort optional, notes; для бега: дистанция, продолжительность, средний темп (вычисляется только при наличии обоих значений); для силовых: упражнения, подходы, повторения, вес и рекорды.
- План/факт тренировок; графики дистанции, объёма, тренировочных дней и прогресса упражнений, без медицинских выводов.
- День отдыха не считать пропущенной тренировкой. Не обещать встроенную Apple Health-интеграцию в Windows; возможен отдельный импорт позднее.

### 3.7 Аналитика / Insights
- Диапазон дат 7/30/90 дней/произвольный; KPI и тренды: завершено/создано, недельный план исходный vs финальный, вовремя/просрочено, перенесено, время по проектам, оценка vs факт, фокус-сессии, тренировки, учёба.
- `Efficiency Score` (0..100) как настраиваемый индекс из: выполнение исходного плана 35%, своевременность 25%, фокус 20%, точность оценки 10%, регулярность **запланированных** тренировок 10%. Это начальные веса, редактируемые пользователем. Компоненты, по которым нет наблюдений, исключать и перенормировать веса; показывать `недостаточно данных`, если нечего измерять. Не принимать 0/0 за 100% без объяснения.
- Отдельный график недель, heatmap по выполненным задачам, бар план/факт, распределение времени, график нагрузки; для каждого формула/tooltip. Не создавать необоснованные выводы о психологических качествах.
- Недельные snapshots и event log для воспроизводимости вычислений; history must not rewrite itself when task rescheduled or edited.

### 3.8 Фокус / Deep Work
- Большой таймер, Pomodoro и свободный режим, выбор задачи/проекта, пауза, восстановление после случайного закрытия, системные уведомления по окончании.
- Сохранение сессий, реальное время через system clock+monotonic strategy, чтобы сон компьютера и переключение окон не добавляли лишние секунды бесконтрольно. При неожиданном завершении приложения сессия восстанавливается или корректно помечается прерванной.
- График фокус-времени и список последних сессий, ссылки на задачи.

### 3.9 Заметки / Knowledge Base
- Трёхколоночный layout, Markdown (preview/editor), теги, быстрый поиск, привязка к задачам/проектам/предметам, безопасные локальные изображения/файлы, autosave.
- Не выполнять HTML/JS из Markdown; sanitizer, blocked remote resource loads by default. Экспорт заметки .md.

### 3.10 Настройки / Control Panel
- Тема Premium Forest, плотность UI, размер текста, анимации, hotkeys, стартовый экран, рабочая неделя, часы, язык ru-RU, часовой пояс.

## 4. Структура данных и инварианты

Предлагаемые сущности (допускается нормализовать):
- `projects`, `project_milestones`, `tasks`, `task_checklist_items`, `task_dependencies`, `tags`, `task_tags`, `task_events`, `task_attachments`.
- `weekly_plans`, `weekly_plan_items`, `weekly_plan_snapshots`, `daily_plans`, `task_schedules`, `calendar_events`, `planning_rules`.
- `study_subjects`, `study_aggregate_counts(subject_id,kind,total,completed)`, `study_work_groups`, `study_works(group_id,number)`, `study_stage_definitions(group_id,sort_order,name)`, `study_stage_status(work_id,stage_id,status,updated_at)`, `study_grade_fields`.
- `workout_templates`, `planned_workouts`, `completed_workouts`, `exercises`, `workout_sets`, `running_sessions`.
- `focus_sessions`, `notes`, `note_links`, `attachments`, `dashboard_layouts`, `app_settings`, `change_log`, `schema_migrations`.

Use uuid/ulid IDs, date and nullable semantics explicit. При удалении предмета каскадно удаляются его детальные работы **только после подтверждения**, при удалении проекта задачи сначала предлагается переназначить/архивировать. Уникальные constraints: `(group_id,work_number)`, `(work_id,stage_id)`, `(subject_id,aggregate_kind)`. Checks: `total>=0`, `0<=completed<=total`, `duration>=0`, `distance>=0`; timestamp и единицы измерения документированы. Разные источники учебных данных (aggregate vs per-item) не суммировать без явного режима синхронизации.

Все изменения статуса задачи/учебной работы/тренировки записываются атомарно; пользователь видит обновление сразу с rollback при ошибке. Использовать транзакции и интеграционные тесты на целостность.

## 5. Бизнес-логика планирования

- Задача может быть в `weekly_plan` без `plannedDate`. Перенос по дням **не создаёт новые task ID**.
- В момент фиксации плана сделать `weekly_plan_snapshot`: фиксируются ID, вес, оценка трудоёмкости, срок. Итог двух метрик: исходный план и вся выполненная работа; изменения задним числом не меняют исходную метрику.
- Smart Planner: детерминированный алгоритм из доступных слотов, предельной нагрузки, дедлайна, приоритета и ограничений. Сначала preview + конфликты + ручное подтверждение. Не утверждать AI-прогноз без алгоритма/данных.
- Блокировка пересечения событий — предупреждение и выбор, а не молчаливое затирание.
- Recurrent tasks создают occurrence, а не стирают историю выполнения предыдущих периодов.

## 6. Поведение приложения и UX

- Onboarding: пустой workspace или опциональный импорт референса учёбы, настройка категорий и правил, создание первой задачи.
- Autosave при действиях, уведомление об ошибках с предложением повторить, данные не пропадают при закрытии/перезапуске.
- `Ctrl+K` глобальные команды, `Ctrl+N` задача, `Ctrl+Z` отмена последних допустимых действий, навигация клавиатурой, видимый focus ring.
- Хранить выбранные фильтры и раскладку; быстрые действия на главной и на каждой странице.
- Продуманные loading/empty/error/confirmation/undo states. Не делать неработающие декоративные блоки.
- Доступность: aria labels для чекбоксов учебных этапов и drag-and-drop fallback, контраст, tooltips, reduced motion.

## 8. Тесты и критерии приёмки

### Основные сквозные сценарии
1. Создать проект, задачу, добавить в недельный список, назначить на четверг, запустить Focus, завершить задачу; после перезапуска все данные и статистика совпадают.
2. Создать недельный snapshot, перенести просроченную задачу на следующую неделю: исходная метрика не переписывается; факт виден правильно.
3. Учёба: при импорте значения сводной таблицы совпадают с screenshot; №4 физической лабораторной `Выполнена=done`, `Защищена=not_done`; переключить защиту в `done`, перезапустить — отметка сохранилась; перейти обратно и проверить.
4. Учёба: различать пустое/«-»/«+». Например `Физика ДЗ №2 — Защита теор` сначала unknown, тогда как `МД лаба №3 — Выполнена` not_done.
5. Учёба: не удвоить прогресс агрегированных РК/ДЗ при добавлении детализации; значения `Экз`/`Итог` при первоначальном импорте null.
6. Тренировки: запланировать бег, отметить выполненный пробег, проверить план/факт, тенденцию и отсутствие штрафа за день отдыха.
7. Analytics: пустая база не показывает фальшивые 100%, zero-division отсутствует; все показатели соответствуют ручному контрольному набору.
8. Закрыть и снова открыть приложение на Windows; заметки, графики, виджеты, фильтры и настройки сохраняются.
9. Backup → удалить тестовую сущность → Restore: полное восстановление данных, без дубликатов или потерь, безопасное подтверждение.
10. Работа полностью без сети, отсутствие необязательных внешних вызовов, интерфейс отзывчив при 1000+ задачах.

### Качество
- `typecheck`, `lint`, unit, integration, critical E2E — green.

- Не менее одного скриншота каждого из 10 экранов из реально запущенного приложения в `docs/screenshots/`, а не из генератора картинок.
