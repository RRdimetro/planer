# FOCUS OS PRO 0.2.0 — release candidate

Локальное русскоязычное приложение Windows: 10 утверждённых разделов, Premium Forest, SQLite в Electron main process. Продолжение 0.1.0, без переписывания с нуля. Учебный импорт 9 предметов / 4 группы / 54 статуса сохранён.

**Windows NSIS/portable собраны кросс-сборкой на Linux. Установка и выполнение на Windows НЕ ПРОВЕРЕНЫ; это кандидат, а не принятый Windows-релиз.** Статус: [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md), [Windows status](docs/reports/0.2.0/05-windows-status.json).

## Запуск из исходников на Windows 10/11 x64

Node.js 22.18+ (LTS 22 рекомендуется), pnpm 10.20.0, PowerShell в каталоге проекта:

```powershell
corepack enable
corepack prepare pnpm@10.20.0 --activate
pnpm install --frozen-lockfile
pnpm rebuild
pnpm dev
```

Первое скачивание зависимостей требует сети. После установки обязательной сети/сервера/регистрации нет. Vite используется только в dev; production загружает локальные файлы. При ошибке `NODE_MODULE_VERSION` закройте приложение и повторите `pnpm rebuild` — SQLite должен соответствовать Electron, не системному Node. При отсутствии prebuilt binding Windows может потребовать Visual Studio C++ Build Tools и Python для native rebuild.

## Сохранение и миграции

Данные: `%APPDATA%\FOCUS OS PRO\focus.db`, WAL. Откройте каталог через Настройки. IDs и действующие записи сохраняются при обновлении.

Миграции additive и версионированы: v1 legacy, v2 normalized core, v3 planning constraints/triggers/attachment digest archive. Перед переносом файловой базы создаются `focus.db.pre-vN-<timestamp>.sqlite` и `focus.db.migration-check-<timestamp>.sqlite`. Копия содержит WAL-данные; миграция сначала выполняется на ней. Проверяются точное соответствие legacy DTO, SQL FK, integrity и открываемость оригинальной копии. Затем применяется транзакция рабочей базы. Legacy `records` сохраняется как архив и больше не используется для новых CRUD.

Если исходная база содержит несогласованные связи, приложение откажется от переноса и сохранит v1/v2 для диагностики; оно не удаляет неизвестные записи и не создаёт новую пустую базу. Не удаляйте файлы базы вручную. Для восстановления исходной копии: закройте приложение, сохраните весь каталог данных отдельно и используйте pre-vN SQLite с соответствующей версией приложения. Работа миграций проверена на тестовых копиях, созданных настоящим Store 0.1.0; пользовательская личная база к сессии не прикладывалась.

## Задачи и календарь

Подзадачи, checklist, зависимости, повторы (дни/недели/месяцы), файлы до 25 МБ, массовые операции, Kanban/таблица/иерархия, сохраняемые фильтры. Циклы запрещены SQL; зависимая задача не завершается до её зависимостей. Следующее повторение создаётся отдельным ID после завершения текущего; сохраняются история, исходный день месяца и сдвиг дедлайна. Это не бесконечная заранее развёрнутая серия.

Неделя начинается с понедельника. Задача может быть в недельном списке без дня; назначение дня не дублирует ID. В поле недели можно указать любую дату — сохранится понедельник соответствующей недели. Старые недельные задачи без известной недели остаются плавающими до явного назначения. Исходный weekly snapshot не меняется при последующих переносах.

День/неделя/месяц, DnD задач/событий/тренировок. Длительность меняется нижней ручкой или стрелками ↑/↓ на ней. Рабочие дни/часы, дневной предел, пары, дорога, тренировки, отдельные запреты времени/сложных задач. Smart preview учитывает интервалы, дедлайн, приоритет, зависимости и ограничения; применение атомарно и проверяет, не устарел ли предпросмотр. Пересечения при ручном изменении требуют решения пользователя.

## Тренировки, фокус, заметки

Программы, упражнения, подходы/повторы/вес, беговое время/дистанция/темп. План не считается фактом: программы создают неотмеченные подходы; объём/PR берутся из выполненных подходов завершённых тренировок. Дни отдыха не штрафуются. Будущая тренировка не считается пропущенным наблюдением в Efficiency Score.

Фокус: Pomodoro/free, задача, пауза/продолжение/завершение, история, восстановление прерванной сессии. Сон/длительный провал tick не добавляет время. Системные уведомления возможны только при работающем процессе.

Markdown-заметки: поиск, теги, связь с проектом, autosave, preview/export. HTML/JS и удалённые картинки не выполняются/не загружаются. При быстром переходе и закрытии окна pending-изменения сохраняются до закрытия SQLite. Если сохранение не удалось, окно остаётся открытым с ошибкой.

## Учебный трекер

Импорт референса добровольный; при существующих предметах повторный импорт ничего не меняет. Клик: done ↔ not_done; Alt+клик/правая кнопка: unknown. РК/ДЗ — отдельные агрегаты, детальные этапы их не удваивают. Экз/Итог исходно null. Один клик обновляет одну SQL-ячейку, не timestamps остальных.

## Backup и изолированный дизайн-предпросмотр

ZIP содержит manifest/schema, SHA-256 данных/истории/SQLite, сами SQLite/JSON, связи и байты вложений. Restore валидируется и выполняется транзакционно после подтверждения; старые ZIP v1 читаются. Перед restore создаётся `before-restore.json`. Старые undo snapshots после restore очищаются. Пределы: 25 МБ на вложение; ZIP-компонент до 512 МБ, суммарно до 1 ГБ. JSON экспорт включает байты вложений. Данные резервной копии не шифруются.

Настройки → «Открыть дизайн-предпросмотр» запускает отдельный процесс с каталогом `%APPDATA%\FOCUS OS PRO Design Preview 0.2`. Рабочая база не копируется. Демо постоянно помечено, ZIP/JSON из демо нельзя импортировать в рабочий режим и наоборот. Тестовые/демо-показатели никогда не выдаются за личные данные.

Ctrl+K — команды/поиск, Ctrl+N — задача, Ctrl+Z — отмена обычных действий текущего запуска вне текстовых полей. Виджеты главной переставляются drag-and-drop/↕ и меняют высоту нижним правым уголком.

## Windows CI и история проекта

`.github/workflows/windows.yml` использует Windows Server 2022 runner. `scripts/windows-install-smoke.mjs` отказывается запускаться на Linux. Workflow действительно устанавливает baseline 0.1.0, обновляет его до 0.2.0, проверяет установленное приложение и сохраняет отчёты/скриншоты. Здесь workflow не был запущен: нет Windows executor и авторизованного GitHub remote.

Для проверки обновления нужен commit 79764b5. Архив исходников содержит `repository.bundle` с полной историей. Можно восстановить репозиторий:

```powershell
git clone repository.bundle focus-os-pro
cd focus-os-pro
```

После добавления своего remote и push запускайте Windows workflow. Он не пометит update test успешным, если baseline отсутствует. Cross-build helpers `prepare-win-cross.mjs`/`build-win-cross.mjs` документируют создание текущих Windows-артефактов из Linux; это не замена Windows CI.

Отчёты этапов: `docs/reports/0.2.0/`. Скриншоты: `docs/screenshots/0.2.0/user/` и `demo/`; все сняты в работающем Electron.
