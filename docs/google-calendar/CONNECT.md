# Google Calendar в FOCUS OS PRO

Источник — Google Calendar. Подключение Google Calendar в ChatGPT не выдаёт доступ отдельному Windows-приложению.

## Первое подключение

1. В своём проекте Google Cloud включите **Google Calendar API**.
2. Настройте OAuth consent screen / Google Auth Platform. Для личной проверки в режиме Testing добавьте свой Google-аккаунт в Test users.
3. Создайте OAuth client ID типа **Desktop app**, скачайте JSON. Сохраните его вне исходного проекта и общих папок. Не отправляйте токены и пароли в чат.
4. В FOCUS откройте **Настройки → Интеграции → Google Calendar → Выбрать OAuth Desktop JSON**.
5. Нажмите **Подключить Google**. Вход и согласие выполняются вами в системном браузере. Приложение запрашивает только чтение списка календарей и событий.
6. Используйте аккаунт, где находится «расписание Дима». Если точных совпадений несколько, выберите нужный календарь по идентификатору и часовому поясу.
7. Дождитесь успешной синхронизации. Проверьте события на главной и в дневном, недельном и месячном календаре.

OAuth использует PKCE и локальный loopback callback. Не отключайте firewall, проверку TLS или защиту браузера. При блокировке авторизации проверьте настройки собственного Cloud-проекта и доступ Test user; не обходите предупреждения безопасности.

## Работа с расписанием

- Google — основной источник. Меняйте занятия в Google Calendar, затем нажимайте «Синхронизировать» или дождитесь обновления.
- События, повторения и исключения кэшируются локально. Без сети остаётся ранее загруженное расписание. В настройках показаны время последнего успеха и доступный период.
- По умолчанию загружается период от 90 дней назад до 400 дней вперёд. Периоды вне кэша пока не подгружаются при листании календаря.
- Дорога по умолчанию: 90 минут перед первым и 90 минут после последнего занятия дня. Значения можно менять; дорога виртуальная и в Google не записывается.
- Расписание и дорога учитываются как занятость. Предложения по задачам применяются только после подтверждения предпросмотра.
- «Отключить» удаляет локальные OAuth-токены и останавливает обновление. Сохранённое расписание остаётся доступным. «Переподключить» запускает новый вход.
- При истёкшем или отозванном доступе приложение предложит повторное подключение. Для OAuth-приложений в режиме Testing срок refresh token может быть ограничен настройками Google.

## Хранение и резервные копии

Google-события находятся в отдельных SQLite-таблицах и не заменяют ваши задачи. Перед миграцией создаётся проверенная SQLite-копия и выполняется пробная миграция. ZIP-копия включает кэш расписания, но не OAuth-секреты.

OAuth-клиент и токены зашифрованы Windows DPAPI через Electron safeStorage в отдельной папке `FOCUS OS PRO Credentials` внутри AppData. Нет открытого текстового fallback. После восстановления кэша из ZIP требуется повторное подключение Google.

## Статус проверки

Автоматические сценарии с тестовыми ответами API не равнозначны реальному OAuth. Интеграция считается принятой только после входа пользователя в Windows и появления настоящих событий выбранного календаря в планировщике.

Официальные сведения: [OAuth Desktop](https://developers.google.com/identity/protocols/oauth2/native-app), [Calendar scopes](https://developers.google.com/workspace/calendar/api/auth), [incremental sync](https://developers.google.com/workspace/calendar/api/guides/sync).
