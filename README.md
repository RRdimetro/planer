# FOCUS OS PRO 0.3.0 — Obsidian Command Center

Локальное приложение Electron + React/TypeScript + SQLite для Windows 10/11 x64. Продолжение существующей кодовой базы. Утверждённый вариант B используется на всех десяти страницах. Работает без сети после установки, данные между запусками сохраняются. Реальные данные и дизайн-предпросмотр находятся в разных базах.

**Windows-кандидат пока не принят:** установщик и portable проходят кросс-сборку и статические проверки; реальное выполнение Windows/CI в текущей среде недоступно. Нельзя считать установку, обновление, доставку уведомлений или Windows DPI проверенными. Статус и свидетельства: `docs/reports/obsidian/F/`.

## Windows: запуск из исходников

Установите Node.js 22+ и pnpm 10.20.0, затем в PowerShell в распакованном каталоге:

```powershell
corepack enable
corepack prepare pnpm@10.20.0 --activate
pnpm install --frozen-lockfile
pnpm run rebuild
pnpm build
pnpm dev
```

`pnpm run rebuild` собирает SQLite для Electron; системный Node имеет другой ABI. При отсутствии prebuilt binding нужны Visual Studio C++ Build Tools и Python. Первое скачивание зависимостей требует сети. Production открывает локальные файлы, не требует сервера, регистрации или облачной синхронизации.

```powershell
pnpm dist:win
```

Собирает NSIS Setup.exe и Portable.exe в `release/`. Обычный запуск установленного приложения сохраняет SQLite в `%APPDATA%\FOCUS OS PRO\focus.db`. Portable использует тот же каталог приложения; переносимым является исполняемый файл, данные не записываются рядом с ним. ZIP-копия переносит данные на другой компьютер.

## Начало работы и обновление

На первом запуске выберите пустое рабочее пространство или импорт исходного учебного референса. Предметы не заменяются демонстрационными записями. Импорт содержит ровно 9 предметов, 4 группы и 54 известных tri-state значения; неизвестное отличается от невыполненного, неизвестные оценки остаются пустыми.

Перед установкой кандидата на существующую Windows-систему сохраните ZIP-копию и закройте приложение. Сохраните также весь каталог `%APPDATA%\FOCUS OS PRO`. Используются additive-миграции v1–v5: сначала проверка на копии с WAL, затем перенос с проверкой точного соответствия записей/FK; открываемый pre-vN original остаётся рядом. При ошибке исходная база не очищается. Распаковка новой программы не требует удаления старой базы.

Копии: «Настройки → Создать ZIP-копию». Архив содержит JSON, SQLite, байты вложений и историю с SHA-256. Перед заменой или ротацией копия пробно восстанавливается и проверяется. Автоматические копии по умолчанию раз в 24 часа, последние 7, каталог `backups` внутри данных; настройки меняются в приложении. Ручные и предмиграционные файлы не ротируются. Перед импортом/восстановлением сохраняется отдельная копия. Восстановление ZIP заменяет текущие данные после подтверждения.

## Десять разделов

- **Главная:** утверждённая композиция B, реальные дневные/недельные показатели, расписание, проекты и фокус. Настройка видимости/порядка/ширины/высоты виджетов ниже основной сетки; сброс возвращает эталон.
- **Планировщик:** день 00–24, неделя, месяц, список. Перенос и изменение длительности мышью/клавиатурой, повторные события, конфликты, свободные окна, пары/дорога/ограничения. Автораспределение сначала предлагает план; применение отдельно и с проверкой revision.
- **Задачи:** Kanban, измеряемая виртуальная таблица, недельный список/backlog и иерархия. Подзадачи, чек-листы, зависимости, вложения, повторы, категории, поиск/фильтры, массовые изменения. Исходный недельный план фиксируется явно и не переписывается переносом.
- **Проекты:** цели, этапы, weighted progress, задачи, зависимости, Kanban, Gantt, материалы и активность. Прогноз только при наличии минимум трёх реальных завершений за 14 дней.
- **Учёба:** один клик меняет одну ячейку; Alt/right click или ? возвращает неизвестное. Группы можно расширить, известные статусы сохраняются. РК/ДЗ по подробным работам пересчитываются только после явной привязки агрегата к одному этапу.
- **Тренировки:** программы, упражнения, подходы/повторы/веса, бег/темп, объём, PR, недельное расписание и сравнение периодов. Фактом являются завершённые тренировки и подтверждённые подходы.
- **Аналитика:** Daily/Weekly Efficiency, сроки, план/факт, фокус, переносы, просрочка, графики/heatmap/donut, проекты и тренировки. Период до 366 дней, фильтры проекта и категории, сравнение с предыдущим периодом той же длины.
- **Фокус:** Pomodoro, свободный таймер, отдельные перерывы, задача, длительность, fullscreen, журнал. Таймер в main process, сворачивание и тяжёлая работа учитываются; сон ОС исключается. Перерывы не входят в рабочие метрики. После закрытия сессия открывается прерванной и требует продолжения.
- **Заметки:** Markdown, папки, теги, поиск, проекты/задачи, вложения и локальные изображения, внутренние ссылки/backlinks, история версий. Автосохранение сбрасывается до перехода и закрытия. Восстановление версии создаёт новое изменение.
- **Настройки:** масштаб, плотность, уменьшение движения, часовой пояс, планирование, веса эффективности, уведомления, копии/импорт/диагностика, отдельное demo-окно.

Ctrl+K — команды и поиск; Ctrl+N — задача; Ctrl+Z вне текстового поля — отмена; Esc — закрыть панель. Уведомления работают при запущенном приложении, включая свёрнутое; срок без времени напоминается в 18:00. Разрешение на показ управляется ОС.

## Excel

«Учёба → Экспорт Excel» создаёт настоящий `.xlsx`. Для импорта используйте его структуру: `Предметы` и `Работы`, ID/предмет/этап/номер работы/статус. Импорт показывает количество изменений и создаёт копию, затем атомарно объединяет данные; записи вне файла остаются. При добавлении новых строк ID можно оставить пустым. Формулы сначала преобразуйте в значения. Произвольные старые `.xls` и мастер сопоставления колонок не поддерживаются. Demo-XLSX/ZIP/JSON нельзя импортировать в пользовательскую базу и наоборот.

## Изолированное demo

В настройках нажмите «Открыть дизайн-предпросмотр». Отдельное окно имеет постоянную маркировку. Рабочая база не меняется. Из исходников после build:

```powershell
pnpm preview:design
pnpm preview:design --empty
```

Единственный актуальный дизайн — B. Исторические A/C в репозитории не являются режимами текущего приложения.

## Проверки и Windows CI

```powershell
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm test:obsidian
node scripts/obsidian-calendar-e2e.mjs
node scripts/obsidian-capture.mjs F
```

Vitest запускается через Electron Node mode, чтобы ABI SQLite совпадал. GUI-проверки используют отдельные временные базы. В текущей Linux-среде использован Xorg :102; тестовый `--no-sandbox` не добавляется в обычный запуск.

Workflow `.github/workflows/windows.yml` подготовлен для настоящего Windows Server 2022 runner: native build, unit/GUI, снимки трёх размеров, реальные NSIS install/update/restart/backup. `windows-install-smoke.mjs` запрещён на Linux. Workflow **не запускался здесь**: нет Windows executor и подключённого git remote. Для upgrade fixture нужна полная история, поставляется `repository.bundle`; её можно клонировать `git clone repository.bundle focus-os-pro`. Нужны push в свой репозиторий и реальный результат CI. Ручные Windows 10/11 проверки остаются отдельной границей.

## Ограничения

- Windows runtime/installation/update/DPI/OS notification delivery и подпись не приняты; бинарники unsigned, помечены UNTESTED.
- Сессии в исторических графиках относятся к дню начала; распределение по полуночи/DST по отсутствующим интервалам паузы не выдумывается.
- Daily использует текущий план датированных задач, Weekly — явно зафиксированный недельный план; отсутствующие компоненты исключаются с перенормировкой весов.
- События материализуются ограниченной серией 2–104; отдельная встреча редактируется независимо. Повтор задачи создаёт следующую occurrence после завершения текущей.
- Восстановление — целая ZIP-копия, не выборочное объединение двух архивов. Уведомления требуют запущенного приложения, system tray/background Windows service не реализован.
- В панели истории отображаются последние 100 записей из максимум 1000 загруженных; полный журнал сохраняется в SQLite и ZIP. Активность проекта в UI показывает изменения проекта и его задач; изменения этапов дополнительно остаются в общем журнале.
- Изображения — локальные PNG/JPEG/GIF/WebP до 10 МБ; вложения до 25 МБ. Удалённый HTML/изображения не исполняются. ZIP-компонент до 512 МБ, сумма до 1 ГБ.

Подробные этапы, проверки и ограничения: `IMPLEMENTATION_STATUS.md`, `docs/reports/obsidian/A–F/`. Все PNG в `docs/screenshots/obsidian/` сняты с настоящего Electron, не с макетов. Приложение содержит только десять утверждённых разделов.
